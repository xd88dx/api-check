# api-check · 验收清单（ACCEPTANCE）

> 监工（ZCode）按本清单逐条验收。每批先过通用门槛 A 组，再过该批专项；任一条不过即整批打回，缺陷以「文件+行+判据」形式反馈。OpenCode 在每批报告中须自报 A 组各项的执行结果（命令输出摘要），不得只报「已完成」。

## A. 通用门槛（每批必查）

- **A1 构建**：`pnpm build` 与 `pnpm test` 全绿（0 fail）；`tsc --noEmit` 零错误。报告附输出摘要。
- **A2 行尾**：`git ls-files --eol` 除 `*.bat` 外全部 `i/lf w/lf`。
- **A3 key 泄漏**：`grep -rn "sk-" --include="*.ts" --include="*.tsx" --include="*.md" .`（排除 `data/`、mock 占位 `sk-test-*`、mask 实现本身）零真实命中；抽 3 条 API 响应与日志行确认掩码形态 `sk-84…GVEQJ` 式。
- **A4 依赖**：`package.json` diff 对照 SPEC 白名单，新增依赖未经批准即打回。
- **A5 结构**：逐页面/逐 tab 浏览器实测，无「一处崩溃吞掉整个面板」；单文件 ≤ 500 行（`wc -l` 抽查超限文件）。
- **A6 git**：本批恰一次 commit、message 规范、无 push、`docs/` 两文件无改动。
- **A7 测试真实性**：抽查 vitest 是否真断言（防「测试永远绿」的空转测试：无断言/断言恒真的直接打回）。

## B. M1 专项（骨架）

- **B1** 渠道 CRUD：建/改/删/启停全流程；删除有二次确认；重启进程后渠道与密钥完整恢复。
- **B2** 掩码：面板所有出现 key 处均为 `sk-84…GVEQJ` 形态；编辑回填不泄露明文（编辑框留空=不改）。
- **B3** 原子落盘：并发写单测（模拟同时写 config 两次）不产生半截文件；临时文件清理干净（`data/` 下无 `.tmp` 残留）。
- **B4** i18n：中英切换即时生效、刷新后保持；切到 en 后逐页抽查无裸中文（对称检查 zh 无裸英文）。
- **B5** 启动：`start.bat` 双击可用、Ctrl+C 停止、`data/logs/start.log` 持续追加。
- **B6** API 校验：zod 对非法 body（缺字段/类型错）返回 400 带字段级信息，不 500。

## C. M2 专项（探测与目录）

- **C1** mock 上游五分类：2xx→ok、404→unsupported、401→auth、429→rate_limited（**黄色**）、挂住→timeout；每类一条 vitest 断言 + 浏览器实测截图描述。
- **C2** URL 归一化：输入 `https://x.com/v1`、`https://x.com/v1/`、`https://x.com` 三形态，四协议拼接结果符合 SPEC §4 表（Anthropic/Gemini 剥尾 `/v1`，OpenAI 不剥）。
- **C3** 透传：unsupported/auth 的 `rawSnippet` 含上游错误原文（mock 中预置特征串验证未被改写）。
- **C4** 目录：mock 返回 5 模型 → chips 出现 5 条；返回空 → 明确报错且**现有目录不被清空**；手动添加模型不受同步影响。
- **C5** contextHint：目录带 context 字段时 chips 显示，无该字段时不显示且不报错。

## D. M3 专项（矩阵）

- **D1** 串行：mock 上游记录请求到达时刻，任意两次间隔 ≥ 配置的 intervalMs（vitest 断言），UI 侧无并行齐射。
- **D2** 中断：3 模型×2 key 运行中点停止 → 队列清空、`stopped:true` 落盘、已完成格保留、无僵尸请求（mock 记录请求数与完成数一致）。
- **D3** 静默超时：mock 「头已到、body 永不吐」→ 按 timeoutMs 判 timeout（测试配 2s 加速），**不是**等满整体计时才失败；正常慢响应（每秒吐一字节、总长 > timeoutMs 的若干倍）不被误杀。
- **D4** 429 语义：矩阵中 429 格黄色显示「限流」；「只选可用」预览 diff 中 429 模型**不被剔除**；应用后勾选集与预览一致。
- **D5** 耗时：<1s 显示 `NNN ms`、≥1s 显示 `N.N 秒`（两种 mock 延迟各验一）。
- **D6** 结果持久化：矩阵跑一半重启 → 已完成格结果与运行状态（stopped）恢复显示。
- **D7** 互斥：矩阵运行中再发 probe/catalog/test → 409。
- **D8** i18n 审计脚本可运行并输出清单。

## F. 验收流程与打回机制

1. OpenCode 每批完成 → 报告附 A 组自检结果（命令输出摘要）+ 该批专项自评 → 停等。
2. 监工验收顺序：A 组 → 批专项 → 随机抽查（代码 review 重点：runner 队列实现、原子写、分类判定、mask 收口）。
3. 打回：缺陷清单逐条给「文件+行号+违反的条款号+复现方式」；OpenCode 修复后**整批重验**（不是只验缺陷项）。
4. 里程碑放行权与范围变更权在用户；OpenCode 与监工均不得单方面扩范围。
5. 生产排查期（验收后）：问题按「上游官方限制 / 本机环境 / 程序缺陷」三分法归因后修复，修复须补对应 vitest 回归用例。

- **G2 列头**：中文 `密钥 crow-main`、英文 `Key crow-main`。
- **G3 目录过滤**：输入 `qwen` 只剩 qwen 系 chips；清空全恢复；过滤中勾选状态保留；重取目录后过滤词仍生效。

## H. M6 专项（对照 SPEC §13）

- **H1 卡片满行**：编辑页四区块卡片宽度一致占满容器，无半行空隙（768px 窄屏同样成立）。

## I. M7 专项（重试语义，对照 SPEC §14）

- **I1 重试直至成功**：mock 首两次 503 第三次 200（N≥3）→ 格最终 ok 且延迟=第三次真实值、带「重试 2 次后成功」；N=2 同场景 → 全败显示 503 +「重试 2 次均失败」。
- **I2 成功不停手**：首次 ok → 仅 1 次请求（vitest 断言请求数）；首次 429 → 定案 rate_limited 不重试。
- **I3 重试间隔**：mock 记录到达时刻，重试请求与首次间隔 ≥ intervalMs。
- **I4 UI**：设置标签改「失败重试次数」；格内无连通率形态；标注与 tooltip 双语齐全。
- **I5 回归**：73 用例中与旧连通率语义冲突的用例按新语义改写，其余零回退；A 组照旧。

## J. M8 专项（权限与 Gist 同步，对照 SPEC §15）

- **J1 权限**：设 PANEL_PASSWORD 后——无 x-auth 访问 /api/channels → 401；带正确 x-auth → 200；/api/login 错密码 → 401、对密码 → ok；静态页与登录框可加载；不设 PANEL_PASSWORD → 全部照旧可访问（本地默认）。
- **J2 前端登录**：401 → 登录 modal 弹出（双语）；登录成功 → 请求重放成功、刷新页面保持登录态（localStorage）；登出/清 localStorage → 再弹。
- **J3 Gist push/pull**：配 token+gist_id → push → Gist 上出现 api-check.json 且内容含渠道（含 key 明文）与勾选；改动渠道 → pull → 本地被 Gist 内容覆盖。
- **J4 三方对比**：本地改（Gist==基线）→ sync 自动推；Gist 改（本地==基线）→ sync 自动拉；两边都改 → 冲突跳过 + 告警信息（mock GitHub API 或真 Gist 一次验证）。
- **J5 指纹稳定性**：跑一次测试/探测（state 变化）→ 指纹不变（不误判为修改）；改 key 明文 → 指纹变。
- **J6 回归**：76 用例零回退 + 新增用例；A 组照旧；i18n 双语无裸文本。
